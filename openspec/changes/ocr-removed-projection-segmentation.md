# 移除 OCR，改用投影切分自动切字 - 变更记录

## 变更信息

- **变更名称**: ocr-removed-projection-segmentation
- **变更类型**: 功能替换（删除 + 新增）
- **完成时间**: 2026-11-01
- **决策依据**: `openspec/changes/ocr-accuracy-tuning.md` 的实测数据

## 为什么删掉 OCR

真机验证结论：通用 OCR 引擎识别毛笔字不可用。

| 引擎 | 印刷体 | 毛笔字 |
|---|---|---|
| Tesseract（chi_sim，psm6） | ✅ | 5/8（62%） |
| PaddleOCR（PP-OCRv2） | ✅ | **0/8** |

两者都是印刷体/场景文字模型，毛笔笔画属于分布外输入。参数调优的天花板已经探到，
继续投入没有意义，因此按用户决定**整体移除识别功能**。

## 新增：投影切分自动切字

### 原理

不回答「字是什么」，只回答「字在哪」——后者是纯几何问题，毛笔字同样成立。

```
灰度 → Otsu 二值化 → 墨迹掩码
  ↓
垂直投影找列间空白 → 列
  ↓
每列内水平投影找字间空白 → 单字框
```

竖排按「列 → 行」切，横排按「行 → 列」切；读序竖排从右往左、横排从左往右。

### 关键参数（`src/utils/segment.js`）

| 参数 | 值 | 作用 |
|---|---|---|
| `INK_RATIO` | 0.004 | 投影占比低于此值视为空白 |
| `GAP_RATIO` | 0.008 | 空白带宽低于此值视为字内笔画间隙，合并 |
| `MIN_SIZE_RATIO` | 0.015 | 过滤噪点 |
| `MERGE_FACTOR` | 1.85 | 超过中位尺寸 1.85 倍视为多字粘连，等分 |

### 版面判定

1. 只有一列 → 竖排；只有一行 → 横排
2. 行数 ≤ 2 且列数 ≥ 3 → 横排
3. 其余默认竖排（书法常态）
4. 面板提供「自动 / 竖排 / 横排」手动切换

### 交互

临摹页底部「自动切字，逐字临摹」→ 抽屉内整幅图叠加切分框 → 点任意框直接进入单字临摹。

## 验证

| 用例 | 期望 | 结果 |
|---|---|---|
| 竖排 4×4 | 16 框 / 竖排 | ✅ |
| 横排 2×5 | 10 框 / 横排 | ✅ |
| 单字 | 1 框 | ✅ |
| 密集 3×3（字距 10px） | 9 框 | ✅ |
| 带噪点竖排 3 字 | 3 框 | ✅ |
| 纯函数单测（`findBands` / Otsu） | 6 项 | ✅ 全通过 |
| 端到端（上传→切分→点框进单字） | 16 框、viewBox 落在最右列 | ✅ |

## 遗留

- 未用真实手机拍摄的字帖照片验证（合成图偏「干净」），透视/阴影可能影响切分
- 粘连严重的行草可能切不准，需手动点选兜底
- 尚未做「切分结果持久化」（每次打开重新计算，耗时约 10-40ms，可接受）
