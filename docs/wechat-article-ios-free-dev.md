## 二、正文内容（可直接发布）

上周改了一行切分参数，跑完 264 项测试，满心欢喜拿起 iPhone——屏幕上还是三天前那个包。😅

那一刻我突然明白：卡住个人开发者的，从来不是那笔每年 99 美元的开发者年费，而是「代码改完了，手机上的包怎么跟着变」。

更扎心的是 AI。它能一口气写完整个函数，却看不见你屏幕上那个切错的字框。你不截图、不描述，它就只能猜。

所以我把这套流程拆了重装：让 AI 自己看、自己测，让 GitHub 自己打包发布，让 iPhone 自己提示更新。全程没有支付开发者年费，没有服务器，也没打开过 Xcode 的签名面板。

这个项目叫「书法临摹助手」，一个把字帖切成单字、逐字放大临摹的本地 App。下面这条链路，每一步都能在仓库里翻到代码。

### 01 先给 AI 装一双眼睛 👀

我在项目里加了一个只在开发环境生效的 Vite 插件：`apply: 'serve'`，生产包和 iOS / Android 包里**一行都不含**。

它做的事很朴素：页面通过 MutationObserver + 3 秒轮询，把「当前打开的字帖原图 + 切分框 + IndexedDB 里的状态」POST 到本机 `/__debug/report`，落到系统临时目录 `calligraphy-debug/`：

- `current.<ext>`：当前页原图，换页覆盖
- `current.json`：这张图是哪一页、多大、从哪来
- `state.json`：`stores.segmentations` 就是**页面上正在显示的那些框**

于是手工测试时，我只要停在出问题的那一页，说一句「我停在当前字帖页，看一下」，不用截图、不用导图片、不用描述。AI 读两个 JSON 就知道是哪张图、屏幕上显示哪些框，再跑 `node scripts/diagnose-segment.mjs` 直接调用生产环境那个 `segmentCharacters`，把阈值、列带、字距逐层打印出来，顺手生成一张带编号红框的叠加图。

逐框一对比，立刻能分清是「算法算错了」，还是「缓存 / 手动编辑造成的差异」。

候选修复也不急着改源码。`scripts/verify-couplet-candidate.mjs` 的范式是：把 `segment.js` 读成文本，在内存里注入候选函数写到 `/tmp` 再动态 import，对同一批掩码做原版 / 候选版 A/B 逐框比对，**全程不碰 `src/`**。确认影响范围后才落地，并且必须把 `SEGMENT_ALGORITHM_VERSION` 加一——否则用户装上新版，还是命中旧缓存，看不到新结果。

护栏是 264 项单元测试和 15 套真实字帖的 golden 快照，报错精确到「哪张图、第几框」。

这条路也踩过两个坑：采集脚本绝不能抢在 App 之前创建 IndexedDB，否则会生成一个 version=5 却零张表的空库，字帖库直接全空——现在先用 `indexedDB.databases()` 确认库存在，再不带版本号打开；另外 Vite 热更新只换组件、不整页 reload，会把「旧框 + 新版本号」写回缓存，固定解法是硬刷新后点一次「重新切分」。

一句话：**不是让 AI 更聪明，是让它拿到和你眼前一样的数据。**

### 02 打一个 tag，剩下的交给 GitHub ⚙️

自动发布由三个工作流接力完成：

- `ci.yml`：push 到 main 或提 PR，Node 22 环境跑 `npm ci` → `npm test` → `npm run build`
- `release-ipa.yml`：推送 `v*` 标签触发，用 `macos-15` runner（自带 Xcode）
- `pages.yml`：main 上 `altstore/**` 有变动就重新部署静态站点

最关键的一步是「未签名 IPA」。`scripts/build-unsigned-ipa.sh` 用命令行编译，把签名整个关掉：

```bash
xcodebuild -workspace ios/App/App.xcworkspace -scheme App \
  -configuration Release -destination 'generic/platform=iOS' \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO \
  CODE_SIGN_IDENTITY="" build
```

然后把 `App.app` 塞进 `Payload/` 打成 zip，就是一个标准 IPA。全程不需要登录 Apple ID，也就不必碰「Xcode 图形界面打不开 / 自动签名不可用」这类环境麻烦。签名这件事，交给手机侧的工具去做。

CI 里还有一步不能省：`npx cap sync ios`。`Pods/`、`capacitor.config.json`、`config.xml` 都被 gitignore，检出后不存在，不补就直接报找不到 `Pods-App.release.xcconfig`。

后面的流水线全是机械动作：算 `size` 与 `sha256`、从 IPA 内的 `Info.plist` 读出最低系统版本 → `gh release create` 上传归档 → 把 IPA 拷进 `altstore/ipa/` → 用一段 Python 把新版本插到 `source.json` 的 `versions[0]` 并同步顶层字段 → 机器人提交推回 main → Pages 自动部署。

本地也留了一条命令：`bash scripts/release-ipa.sh 1.4.0`，加 `--dry-run` 只打印计划不动文件。

三个真实的坑，值得单独记下来：

1. **仓库必须公开**。私有仓库的 Release 直链要鉴权，手机端下载不了。
2. **Pages 构建源选 GitHub Actions**，别选 branch / Jekyll。本仓库用 legacy 构建反复报 `Page build failed.` 还不给原因，站点内容会停在旧版本。
3. **IPA 直链走 `github.io`**。实测国内直连 `github.com` 约 20 秒无响应，而 `caipanjin.github.io` 约 0.6 秒可通。Release 照建，但只当归档和 changelog。

**发版不是一次操作，是一份能被机器重放的描述。**

### 03 让手机自己发现新版本 📱

先说清楚免费账号的边界，免得误会。

Apple 允许免费 Apple ID 以个人团队身份，给自己的设备签名调试 App：证书 **7 天**有效、同时最多 **3 个**侧载 App（AltStore 自己就占一个）、每周大约能注册 10 个 App ID。电脑上的 **AltServer** 在后台运行、手机和电脑在同一 Wi-Fi 时，就能自动续签。这不是什么灰色手法，用的是 Apple 明确留给开发者的那条自测通道；代价也很实在——每周得让电脑在线一次。

手机端只需要做一次：AltStore → Sources → 右上角 `+` → 粘贴源地址：

```
https://caipanjin.github.io/calligraphy_app/altstore/source.json
```

之后每次发版，AltStore 刷新源就会提示升级。

这里有个特别容易搞混的概念：**Refresh 只续 7 天签名，不更新代码**。代码要变，靠的是源清单里 `versions[0].version` 单调递增。这份 JSON 有四个硬约束：

- `version` 必须单调递增，否则 AltStore 不认为是更新
- `sha256` 必须和实际上传的 IPA 一致，对不上直接拒绝安装
- `date` 是带时区偏移的 ISO8601（如 `2026-11-10T09:15:23+08:00`），不是纯日期
- 顶层 `apps[0]` 的 `version` / `versionDate` / `downloadURL` / `size` 要同步成最新版，它决定商店页显示什么

IPA 本身是未签名的，AltStore 用你自己的 Apple ID 重签后安装。**bundle id 保持不变就能原地覆盖升级，IndexedDB 里的练习存档不会丢**——对本地优先的 App 来说，这条比什么都重要。

最后提醒一句：版本号要三处对齐，`package.json`、`project.pbxproj` 的 `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION`、以及 Android 的 `build.gradle`。漏一处，就会出现「发版成功但手机上没反应」。

### 结尾

回头看，这条链路里没有一步是黑科技：免费账号的签名资格是 Apple 给的，AltStore 是开源的，GitHub Actions 有免费额度。真正花时间的，是把「AI 看不见」「手机不会自己变」「手工上传会漏」这三个断点一个个接上。

如果你也在自己写 App，可以先做最小的三件事：给项目写一组能报错到具体位置的测试；加一个只在 dev 生效的状态导出；把打包发布写成一条脚本。等这三步跑顺了，再谈签名。

猜猜这套流程里我最常翻车的是哪一步？我投「改完前端忘了同步到 `ios/App/App/public/`，Xcode 打包的还是上一版」——项目里专门有篇文档记这个坑。你们觉得呢？评论区聊聊 👇

**核心观点**：免费开发者账号能解决签名，但真正卡住独立开发者的不是证书，而是「AI 看不见现场、代码改完手机不会自己变」的反馈闭环；把自测与发布工程化，7 天的签名额度就够用了。
